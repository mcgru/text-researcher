# PRD: text-researcher

## 0. Document Purpose

Этот PRD определяет требования к text-researcher — TUI-приложению для глубокого лингвистического анализа текста. Документ построен на основе Product Brief от 2026-05-26 и описывает функциональные требования, пользовательские сценарии и границы MVP. Глоссарий (§3) фиксирует терминологию; все требования используют термины глоссария без синонимов. Встроенные `[ASSUMPTION]`-теги вынесены в индекс предположений (§9). Документ предназначен для архитектора и разработчика — он даёт достаточную основу для создания Architecture и Epics.

## 1. Vision

text-researcher — это инструмент лингвиста в терминале. Пользователь загружает текст, перемещает курсор по словам и мгновенно видит полный морфологический разбор выделенного слова: часть речи, род, число, падеж, время, лицо и другие признаки. Приложение работает в двух режимах: интерактивный TUI для исследовательской работы и batch-режим для скриптовой обработки текстов с выводом результатов в JSON.

Это не текстовый редактор. Это лингвистический микроскоп: курсор движется — анализ обновляется, без мыши, без веб-форм, без переключения окон. Сессия сохраняется — пользователь закрывает программу и возвращается ровно к тому месту, где остановился. Результаты разбора можно сохранить и экспортировать.

## 2. Target User

### 2.1 Jobs To Be Done

- **JTBD-1:** Когда я читаю текст на иностранном или сложном языке, я хочу мгновенно видеть морфологические признаки любого слова, чтобы понимать его роль в предложении без отвлечения на внешние инструменты.
- **JTBD-2:** Когда я провожу лингвистический анализ, я хочу сохранять результаты разбора, возвращаться к ним позже и при необходимости корректировать автоматические определения, чтобы моя работа не терялась.
- **JTBD-3:** Когда мне нужно обработать большой корпус текстов, я хочу запустить анализ в пакетном режиме и получить структурированный JSON-вывод, чтобы автоматизировать исследовательский пайплайн.

### 2.2 Non-Users (v1)

- Пользователи, ожидающие графический интерфейс (GUI) [ASSUMPTION]
- Пользователи, ожидающие веб-интерфейс
- Пользователи, не знакомые с терминалом и клавиатурной навигацией [ASSUMPTION]

### 2.3 Key User Journeys

- **UJ-1. Лингвист открывает текст и исследует морфологию.**
  - **Персона + контекст:** Алексей, филолог-исследователь, работает с русским художественным текстом. Запускает text-researcher из терминала.
  - **Входное состояние:** Приложение запущено. Предыдущая сессия сохранена.
  - **Путь:**
    1. Приложение автоматически восстанавливает последний открытый файл и позицию курсора. Если предыдущей сессии нет — показывает меню загрузки.
    2. Алексей видит текст в основной панели. Курсор стоит на последнем редактировавшемся слове.
    3. Алексей перемещает курсор стрелками (или vim-подобными клавишами) по словам.
    4. В панели свойств мгновенно обновляется морфологическая информация: «глагол, сов. вид, прош. время, ед. число, муж. род».
    5. Статус-строка показывает: имя файла, позицию в тексте (строка:колонка), текущий язык анализа.
  - **Кульминация:** Алексей видит, что автоматический разбор определил слово неверно. Он нажимает шорткат редактирования, исправляет признаки, изменение сохраняется в рамках данной сессии.
  - **Разрешение:** Алексей нажимает `Ctrl+S` — программа сохраняет проект (текст + все правки разбора + позицию курсора) в файл проекта. В следующий раз всё восстановится.
  - **Edge case:** Если файл был перемещён или удалён между сессиями, программа сообщает об этом и предлагает указать новый путь.

- **UJ-2. Исследователь обрабатывает корпус текстов в batch-режиме.**
  - **Персона + контекст:** Мария, лингвист-корпусник. У неё 50 текстовых файлов для морфологического анализа.
  - **Входное состояние:** Терминал, установленный text-researcher.
  - **Путь:**
    1. Мария запускает `text-researcher batch input.txt -l ru -o result.json`.
    2. Программа загружает модель UDPipe для русского языка.
    3. Программа обрабатывает текст: токенизирует, определяет части речи, морфологические признаки, леммы.
    4. Результат записывается в `result.json` — массив предложений, каждое предложение — массив слов с полным морфологическим разбором.
  - **Кульминация:** Мария получает готовый JSON, пригодный для дальнейшей обработки в её скриптах.
  - **Разрешение:** Мария интегрирует вызов в свой исследовательский пайплайн.
  - **Edge case:** Если файл не найден или модель не загружена — программа завершается с ненулевым кодом возврата и сообщением об ошибке в stderr.

## 3. Glossary

- **Проект** — файл (формат TBD), содержащий: путь к исходному тексту, кеш морфологического разбора, пользовательские правки разбора, позицию курсора, настройки сессии. Расширение: `[ASSUMPTION: .trproj]`.
- **Сессия** — состояние интерактивного TUI-режима: открытый проект, позиция курсора, активная панель.
- **Панель** — прямоугольная область TUI-экрана. В v1: панель текста, панель свойств слова, строка меню, статус-строка.
- **Панель текста (TextPane)** — основная панель, отображающая загруженный текст с подсветкой текущего слова.
- **Панель свойств (PropsPane)** — панель, отображающая морфологические признаки слова под курсором: часть речи, лемма, род, число, падеж, время, лицо, наклонение и т.д.
- **Строка меню** — верхняя строка TUI с выпадающими меню: File (открыть, сохранить, выйти), Edit (отменить правку), View, Help.
- **Статус-строка** — нижняя строка TUI: имя файла, позиция в тексте, язык анализа, статус сохранения.
- **Морфологический анализ** — результат работы UDPipe: токенизация, POS-теги, леммы, морфологические признаки.
- **Пользовательская правка** — ручное изменение морфологических признаков слова в конкретном вхождении. Сохраняется в проекте и имеет приоритет над автоматическим разбором при повторном открытии.
- **Batch-режим** — неинтерактивный режим: программа получает файл и параметры через аргументы командной строки, выводит результат в JSON, завершается.
- **UDPipe-модель** — файл предобученной модели для конкретного языка (.udpipe), загружаемый при старте анализа.
- **Universal Dependencies (UD)** — стандарт лингвистической аннотации, используемый UDPipe. Определяет набор частей речи и морфологических признаков.

## 4. Features

### 4.1 Интерактивный TUI-режим

**Описание:** Основной режим работы. Полноэкранный терминальный интерфейс с несколькими панелями. Пользователь открывает текст, перемещает курсор по словам клавиатурой, видит морфологический разбор в реальном времени. Реализует UJ-1.

#### FR-1: Запуск и восстановление сессии

Пользователь может запустить программу в интерактивном режиме. Если предыдущая сессия была сохранена, программа автоматически восстанавливает проект и позицию курсора.

**Следствия (проверяемые):**
- При запуске без аргументов программа открывает последний сохранённый проект, если он существует
- Если предыдущего проекта нет, программа показывает меню загрузки (File → Open)
- Если файл проекта повреждён или ссылается на несуществующий файл, программа показывает ошибку и меню
- Позиция курсора восстанавливается с точностью до слова

#### FR-2: Отображение текста в основной панели

Пользователь видит загруженный текст в панели TextPane. Текущее слово под курсором визуально выделено (инверсия цветов или другой ясный индикатор). Текст скроллируется при навигации.

**Следствия (проверяемые):**
- Текст отображается с сохранением абзацев и строк
- Текущее слово визуально отличимо от остальных
- При достижении границы панели текст скроллируется
- Поддерживаются кодировки UTF-8

#### FR-3: Навигация по словам

Пользователь может перемещать курсор по словам с помощью клавиатуры.

**Следствия (проверяемые):**
- Стрелки влево/вправо: переход к предыдущему/следующему слову
- Стрелки вверх/вниз: переход на строку выше/ниже с сохранением примерно той же горизонтальной позиции
- Vim-подобные клавиши: `h/j/k/l`, `w/b` (слово вперёд/назад) [ASSUMPTION: базовые vim-клавиши достаточны]
- `Ctrl+←`/`Ctrl+→`: переход к предыдущему/следующему предложению [ASSUMPTION]
- Позиция в статус-строке обновляется при каждом движении

#### FR-4: Панель морфологических свойств слова

При наведении курсора на слово в панели PropsPane отображаются его морфологические признаки, полученные от UDPipe: часть речи, лемма, род, число, падеж, время, лицо, наклонение, залог, степень сравнения и другие признаки из Universal Dependencies.

**Следствия (проверяемые):**
- Свойства обновляются мгновенно (субъективно без задержки) при перемещении курсора
- Если слово не распознано UDPipe, панель показывает «Нет данных»
- Если модель для языка не загружена, панель показывает «Модель не загружена»
- Признаки отображаются в человекочитаемом виде (не коды UD), с переводом на русский [ASSUMPTION]

#### FR-5: Редактирование свойств слова вручную

Пользователь может исправить неверно определённые морфологические признаки слова в конкретном вхождении. Правка сохраняется в проекте и имеет приоритет над автоматическим разбором.

**Следствия (проверяемые):**
- Шорткат (предлагаемый: `e`) открывает диалог или inline-редактор для текущего слова
- Пользователь может изменить любой морфологический признак (часть речи, род, число и т.д.)
- После сохранения правки панель свойств отображает исправленные значения
- При повторном открытии проекта пользовательские правки сохраняются
- Визуальный индикатор показывает, что слово имеет ручную правку [ASSUMPTION]

#### FR-6: Сохранение и загрузка проекта

Пользователь может сохранить текущее состояние работы в файл проекта и загрузить его позже.

**Следствия (проверяемые):**
- `Ctrl+S` сохраняет проект: путь к тексту, кеш морфологического разбора, пользовательские правки, позицию курсора
- `Ctrl+O` открывает диалог выбора файла для загрузки нового текста
- При открытии нового текста предыдущий проект предлагается сохранить, если есть несохранённые изменения
- Формат файла проекта — `[ASSUMPTION: TOML или JSON, решение на этапе Architecture]`

#### FR-7: Меню и статус-строка

Верхняя строка содержит меню (File, Edit, View, Help). Нижняя строка — статус: имя файла, позиция, язык анализа, индикатор изменений.

**Следствия (проверяемые):**
- Меню открывается по `Alt+первая_буква` или `F10`
- File: Open, Save, Save As, Exit
- Edit: Undo Edit (отмена последней ручной правки слова)
- View: переключение фокуса между панелями [ASSUMPTION]
- Help: список шорткатов (About — информация о версии)
- Статус-строка обновляется в реальном времени

#### FR-8: Клавиатурные шорткаты

Пользователь может выполнять частые действия с помощью клавиатурных комбинаций, не открывая меню.

**Следствия (проверяемые):**
- `Ctrl+S` — сохранить проект
- `Ctrl+O` — открыть файл
- `Ctrl+Q` — выйти (с предупреждением, если есть несохранённые изменения)
- `e` — редактировать свойства текущего слова
- `Ctrl+L` — переключить язык анализа (русский ↔ английский ↔ следующий доступный) [ASSUMPTION]
- `Ctrl+C` на слове — копировать лемму в системный буфер [ASSUMPTION]
- `tab` — переключить фокус между панелями
- `?` — показать/скрыть панель шорткатов (quick help)

### 4.2 Batch-режим (CLI)

**Описание:** Неинтерактивный режим для скриптовой обработки. Программа принимает текстовый файл и параметры через аргументы командной строки, выполняет полный морфологический анализ и выводит результат в JSON. Реализует UJ-2.

#### FR-9: Запуск batch-анализа

Пользователь может запустить программу в batch-режиме из командной строки.

**Следствия (проверяемые):**
- Команда: `text-researcher batch <input-file> -l <language> [-o <output-file>]`
- Если `-o` не указан, результат выводится в stdout
- `-l` принимает коды языков: `ru`, `en`, и другие, для которых установлены UDPipe-модели
- При отсутствии входного файла программа завершается с ошибкой (exit code ≠ 0) и сообщением в stderr
- При отсутствии модели для указанного языка программа завершается с ошибкой и сообщением в stderr

#### FR-10: Формат вывода batch-анализа

Результат batch-анализа — структурированный JSON.

**Следствия (проверяемые):**
- Выходной JSON — массив предложений
- Каждое предложение — объект с полями: `text` (строка предложения), `tokens` (массив слов)
- Каждый токен — объект с полями: `word`, `lemma`, `upostag`, `xpostag`, `feats` (объект с морфологическими признаками)
- Формат следует структуре CoNLL-U / UDPipe output [ASSUMPTION]
- JSON валиден, в кодировке UTF-8

### 4.3 Управление языковыми моделями

**Описание:** Приложение использует UDPipe-модели для морфологического анализа. Пользователь должен иметь возможность указать, где находятся модели, и переключать языки.

#### FR-11: Загрузка и переключение языковых моделей

Приложение загружает UDPipe-модель при старте анализа на указанном языке. Пользователь может переключить язык в интерактивном режиме.

**Следствия (проверяемые):**
- Модели ищутся в директории `[ASSUMPTION: ./models/ или задаётся через переменную окружения UDPIPE_MODEL_DIR]`
- В batch-режиме язык задаётся флагом `-l`
- В интерактивном режиме язык по умолчанию — русский [ASSUMPTION: или последний использованный, сохранённый в проекте]
- При переключении языка панель свойств обновляется для текущего слова
- Если модель не найдена, программа показывает сообщение и не падает

## 5. Cross-Cutting NFRs

### 5.1 Производительность

- **NFR-1:** Обновление панели свойств при перемещении курсора — ≤ 50ms (субъективно мгновенно).
- **NFR-2:** Загрузка текстового файла размером до 1 МБ — ≤ 2 секунды.
- **NFR-3:** Потребление памяти в интерактивном режиме — ≤ 256 МБ (без учёта UDPipe-модели в памяти) для текста до 1 МБ.

### 5.2 Код и архитектура

- **NFR-4:** Код на Rust, идиоматичный, но без продвинутых паттернов — читаемый junior-разработчиком.
- **NFR-5:** Обработка аргументов командной строки через современный и удобный парсер (`[ASSUMPTION: clap — стандарт для Rust]`). Поддержка `--help` с авто-генерируемой справкой, понятные сообщения об ошибках при неверных аргументах, автодополнение для распространённых shell (bash, zsh, fish).
- **NFR-6:** Сборка одной командой: `make build`.
- **NFR-7:** Проект упаковывается в Docker-образ одной командой: `make docker`.
- **NFR-8:** CI/CD пайплайн запускает тесты и сборку при каждом пуше.

### 5.3 Совместимость

- **NFR-9:** Поддержка терминалов с поддержкой true color и Unicode (xterm-256color и выше) [ASSUMPTION].
- **NFR-10:** Минимальный размер терминала: 80×24.
- **NFR-11:** Платформы: Linux (основная). macOS — желательно. Windows — не обязательно в v1 [ASSUMPTION].

## 6. Non-Goals (Explicit)

- Программа не редактирует исходный текст — только аннотирует и анализирует
- Программа не является IDE, текстовым редактором или заменой vim/neovim
- Программа не предоставляет веб-интерфейс и не работает как сервер
- Программа не поддерживает коллаборативную работу в реальном времени
- Программа не проверяет орфографию и грамматику
- Программа не переводит текст

## 7. MVP Scope

### 7.1 In Scope (v1)

- Интерактивный TUI: TextPane и PropsPane
- Загрузка текста из файла (.txt, UTF-8)
- Навигация по словам (стрелки + базовые vim-клавиши)
- Морфологический анализ через UDPipe: русский и английский языки
- Меню и статус-строка
- Сохранение/загрузка проекта
- Ручное редактирование свойств слова
- Batch-режим с JSON-выводом
- Make + Docker + CI/CD

### 7.2 Out of Scope for MVP

- Панель связей слов (dependency parsing) → v2
- Диалоги добавления слов в пользовательский словарь → v2
- Присвоение слов классификаторам → v2
- Интеграция с Национальным корпусом русского языка → v2
- Поддержка языков кроме русского и английского → v2 (хотя архитектура должна позволять добавление)
- Подсветка синтаксиса текста [NOTE FOR PM: полезная фича, естественно ложится на v2]

## 8. Success Metrics

**Primary:**
- **SM-1:** Пользователь загружает текст и видит морфологический разбор слова за ≤ 2 секунды от запуска программы. Валидирует FR-1, FR-2, FR-3, FR-4.
- **SM-2:** Batch-анализ текста размером 100 КБ завершается за ≤ 5 секунд (без учёта загрузки модели). Валидирует FR-9, FR-10.
- **SM-3:** Пользователь возвращается к сохранённому проекту и продолжает работу с той же позиции без потери данных. Валидирует FR-1, FR-6.

**Secondary:**
- **SM-4:** 90% автоматических морфологических разборов для русского языка не требуют ручной правки. [ASSUMPTION: измеряется на выборке из 100 случайных слов художественного текста]

**Counter-metrics (do not optimize):**
- **SM-C1:** Время запуска программы — не должно расти линейно с размером файла проекта. Загрузка UDPipe-модели доминирует, и это приемлемо.
